# Phase 2 — إدارة أجهزة الشركة ومراقبتها

## الهدف والنطاق

إضافة تكامل اختياري لإدارة أجهزة iPhone التابعة للشركة إلى BCS، مع تحديث تلقائي لحالة الأجهزة وتطبيق سياسات تقلل الوصول إلى المواقع والمحتوى غير المناسب. هذه المرحلة لا تستبدل وحدات المرحلة الأولى ولا تغيّر سلوكها.

**المرحلة الأولى تبقى محصورة في:**
1. هواتف الشركة
2. حسابات التواصل الاجتماعي

لا تُضاف وحدات أعمال أخرى ضمن هذه المرحلة.

## حقيقة أساسية عن أجهزة iPhone

الأجهزة الحالية غير مسجلة في إدارة مركزية. لا يستطيع موقع BCS وحده مراقبة جهاز iPhone عادي أو اكتشاف التطبيق الأمامي لحظيًا. يلزم تسجيل الأجهزة في حل إدارة أجهزة محمول (MDM) معتمد، ثم ربط واجهة التكامل في BCS بمصدر بيانات موثوق.

يجب عدم الوعد بعرض التطبيق المفتوح حاليًا، أو مدة استخدام كل تطبيق، أو اسم حساب Instagram النشط، ما لم يوفّر مزوّد الإدارة هذه البيانات صراحةً وبطريقة مدعومة من Apple. واجهات MDM القياسية لا تمنح وصولًا عامًا إلى محتوى التطبيقات أو الحسابات المسجّلة بداخلها.

## البنية المقترحة

```text
أجهزة iPhone
    ↓ تسجيل وإدارة عبر MDM
مزوّد MDM (المصدر الموثوق لحالة الجهاز والسياسات)
    ↓ تكامل خادمي موثّق / استقبال أحداث
طبقة تكامل BCS
    ↓ تحقق وصلاحيات وتطبيع البيانات
Supabase (بيانات الجهاز الوصفية وآخر حالة وأحداث التدقيق)
    ↓ Realtime / تحديث دوري احتياطي
واجهة BCS العربية
```

- لا توضع مفاتيح مزوّد MDM أو رموزه السرية في المتصفح أو مستودع Git.
- لا تُحفظ كلمات مرور Apple Account أو رموز الاسترداد أو مفاتيح خاصة أو أسرار API في BCS.
- تُحفظ أقل كمية لازمة من بيانات الحالة، مع سياسات احتفاظ محددة.
- لا تُرسل أحداث MDM مباشرةً إلى المتصفح؛ تمر عبر تحقق خادمي وصلاحيات المؤسسة.
- لا يُعرض الجهاز على أنه «متصل الآن» إلا وفق حداثة آخر إشارة فعلية. تُعرض أوقات آخر تحديث وحالة «قديمة» عند انقطاع الإشارات.
- يُستخدم Supabase Realtime لتحديث واجهة BCS عند وصول تغييرات إلى قاعدة البيانات؛ Realtime لا ينشئ بيانات من الجهاز ولا يجعل MDM يرسل بيانات أسرع مما يدعم.

## مصفوفة الإمكانات

| الميزة | التقييم |
|---|---|
| آخر ظهور / آخر اتصال | ممكن إذا كان مزوّد MDM يوفّر إشارات أو أحداثًا مناسبة؛ لا يُفترض أنه اتصال دائم |
| معلومات الجهاز والتوافق والسياسات | متاحة بحسب الجهاز وإصدار iOS وMDM |
| البطارية / الشحن / الشبكة | لا تُفترض متاحة عبر MDM القياسي لكل جهاز؛ يجب التحقق من واجهة المزوّد |
| قائمة التطبيقات المُدارة أو المثبتة | ممكنة في نطاقات وإعدادات تدعمها Apple وMDM؛ ليست سجل استخدام |
| التطبيق المفتوح الآن | غير مضمون من MDM القياسي؛ لا يُنفّذ كميزة مؤكدة دون إثبات رسمي من المزوّد |
| سجل مدة استخدام التطبيقات | غير مضمون من MDM القياسي؛ يتطلب مصدرًا مدعومًا ومعلنًا إن توفر |
| حساب Instagram المستخدم | غير متاح عادةً عبر MDM؛ لا تُجمع بيانات اعتماد التطبيق ولا يُتحايل على عزله |
| حظر مواقع للبالغين | ممكن باستخدام مرشح محتوى مناسب وسياسة إدارة مدعومة؛ التغطية تختلف حسب المتصفح والتطبيق والشبكة |
| تقييد التطبيقات والإعدادات | يعتمد على التسجيل، والإشراف، وإصدار iOS وسياسات MDM |
| الموقع | ليس ضمن الإصدار الأول؛ يُراجع لاحقًا وفق دعم Apple والحاجة والتصريح والشفافية |

## منع المحتوى غير المناسب

1. اختيار مزوّد MDM/تصفية محتوى يدعم iOS فعليًا، والتحقق من التغطية على Safari والتطبيقات والشبكات المطلوبة.
2. إعداد سياسة تصفية محتوى للبالغين واختبارها على جهاز تجريبي قبل تعميمها.
3. تقييم تقييد التطبيقات أو السماح بقائمة تطبيقات معتمدة إذا كانت مناسبة للعمل ومتوافقة مع Apple.
4. تسجيل حالة السياسة ونتيجة آخر مزامنة، لا تسجيل محتوى شخصي غير لازم.
5. إبلاغ الموظفين بسياسة الاستخدام والمراقبة والحصول على الموافقات اللازمة قبل التفعيل.

لا يجوز اعتبار حظر مواقع الويب ضمانًا لمنع كل المحتوى داخل تطبيقات التواصل أو الفيديو. يجب اختبار كل مسار استخدام، وعدم الادعاء بمنع شامل قبل التحقق.

## التسجيل والترحيل — حماية البيانات أولًا

- ابدأ بجرد الأجهزة الحالية ومعرّفاتها وإصدارات iOS وملكية الشراء/الفواتير.
- تحقّق مما إذا كانت الأجهزة مؤهلة للإضافة إلى Apple Business Manager عبر قناة شراء معتمدة أو Apple Configurator.
- راجع خطوات مزوّد MDM لكل طريقة تسجيل؛ قد تتطلب بعض مسارات التسجيل إعادة إعداد الجهاز أو مسح بياناته.
- **ممنوع تنفيذ مسح أو إعادة ضبط أو تسجيل خروج من Apple Account أو تثبيت ملف إدارة على أجهزة الإنتاج قبل مراجعة أثر ذلك واعتماد خطة ترحيل ونسخة احتياطية مناسبة.**
- اختبر على جهاز واحد غير حرج أولًا، مع موافقة مسؤول الشركة والموظفين حسب السياسة المعتمدة.

## التحديث التلقائي

- واجهة BCS تشترك في تغييرات حالة الأجهزة المخزنة في Supabase Realtime.
- عند عدم دعم الأحداث الفورية من المزوّد، يستخدم الخادم مزامنة دورية بمعدل يحدده المزوّد والحدود المسموح بها.
- كل سجل يحمل `observed_at` أو `last_seen_at` ووقت الاستلام من الخادم؛ لا تخلط بين وقت الاستلام ووقت حدوث الحدث.
- تعرض الواجهة «آخر تحديث» وتوضح البيانات القديمة بدل اختلاق حالة آنية.

## الأمن والخصوصية

- عزل البيانات حسب المؤسسة مع RLS وسياسات خادمية لا تعتمد على إخفاء عناصر الواجهة.
- التحقق من توقيع/هوية webhook أو استخدام API خادمي موثّق وفق توثيق المزوّد.
- أقل صلاحيات ممكنة، وتدوير الأسرار خارج Git والواجهة الأمامية.
- سجل تدقيق للمدير الذي غيّر سياسة أو عرض معلومات إدارية حساسة.
- تحديد الاحتفاظ بالبيانات وإتاحة وصول مناسب حسب الدور.
- لا مراقبة سرية، ولا تجاوز لعزل iOS، ولا جمع لكلمات مرور التطبيقات أو محتواها.
